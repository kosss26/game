# Прохождение: сохранения, таймеры и каталог

Сохранения одной открытой главы отправляются последовательно. Пока запрос идёт,
новые изменения заменяют ожидающий checkpoint. Ошибки и `{ok:false}` показывают
сообщение с повтором; очередь повторяется каждые 5 секунд и при `online`.

До отправки checkpoint сохраняется в localStorage. Ключ включает UUID записи
прохождения и версию сценария: перезапуск истории/главы создаёт другой UUID и
не восстанавливает старый путь. Подтверждённая копия удаляется, только если её
не успело заменить более новое состояние. Восстановление допускается при
совместимой сцене и истории не короче серверной. Сохранения проверяют UUID
прохождения вместе с владельцем/историей/главой: запоздалый запрос от сброшенного
прохождения не может изменить новое. Серверная запись остаётся основной;
localStorage — страховка на том же устройстве, не полноценная офлайн-игра.

Завершение проходит через ту же очередь. Кнопка итогов включается после
подтверждения записи и коллекции концовок; неуспешный запрос остаётся для повтора.
Повтор завершения уже завершённой записи идемпотентен (ответ мог потеряться).
При восстановлении неподтверждённого финала сохраняется его ending ID.

Таймер выбора учитывает только время при видимом документе и активном Mini App.
Обрабатываются visibilitychange и события Telegram activated/deactivated.
Реальные сюжетные паузы «персонаж ответит позже» не меняются.

Каталог: Все / Не начаты / Продолжаю / Пройдены и жанр, совместная фильтрация,
сброс пустой выдачи. При фильтрации выводится весь подходящий каталог, включая
историю из большой карточки и продолжения. Продолжаю включает ожидание главы.
Длительность главы берётся из уже имеющейся авторской оценки minutesPerDay.

Проверки: typecheck, production build, Jest, браузерные проверки фильтров на
320/390/430 px, таймера при скрытии документа дольше лимита и восстановления
checkpoint после ошибки сети. Проверки используют локальную JSON-базу и не
отправляют сообщений реальным игрокам. Нативные события требуют проверки
после обновления на телефоне.

Обновление: обычный deploy/hostkey.sh update, миграция базы и bot setup не нужны.
