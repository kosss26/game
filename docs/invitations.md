# Приглашения и компактное приветствие

Общая иллюстрация `public/share/invitation.jpg` используется в приглашении в игру.
Она не привязана к количеству историй или текущей бесплатной акции.

## Отправка

Кнопки приглашения на главной, в профиле и на странице истории используют
`useInviteFriend`. В Telegram 8.0+ server action `prepareInvitation` проверяет
сессию, берёт Telegram ID из серверного аккаунта и вызывает
`savePreparedInlineMessage`. В результате — иллюстрация, короткий caption и
URL-кнопка в приложение. Клиент вызывает `WebApp.shareMessage`, чтобы игрок сам
выбрал адресата. Приложение не отправляет сообщения друзьям самостоятельно.

Для старого Telegram или ошибки подготовки используется обычный share со ссылкой
`/invite/ref_<id>`. Страница отдаёт OG-метаданные без выполнения JavaScript,
показывает иллюстрацию и кнопку в бот/Mini App с прежним `ref_` параметром.
Личный профиль пригласившего не запрашивается и не публикуется. Невалидные коды
возвращают 404. Страницы помечены noindex/nofollow.

При отмене native picker запасной picker не открывается. Ошибка отправки
обрабатывается отдельно от отмены: кеш карточки сбрасывается, приложение
предлагает открыть отправку обычной ссылки. Это предложение можно отклонить. Пока готовится карточка,
повторные нажатия блокируются; подготовленная карточка кешируется до истечения
срока. Guest/неавторизованный пользователь не может вызвать подготовку от чужого ID.

## Требования

Для native карточки нужен Telegram 8.0+, настроенные `TELEGRAM_BOT_TOKEN`,
`BOT_USERNAME`, публичный HTTPS `APP_URL`. Для Telegram картинка и миниатюра берутся из публичной закреплённой версии
на raw.githubusercontent.com. Эти адреса заданы в `lib/invitations.ts`; они не
зависят от доступности VPS и nip.io со стороны серверов Telegram. Используется существующий
Telegram relay. При его отказе/несовместимости доступна обычная ссылка.
Нативный picker и отображение превью требуют финальной проверки в Telegram после
обновления: локальные тесты используют mock Bot API, сообщений людям не отправляют.

Ссылка CTA сохраняет исходный способ входа: `start=ref_<id>` для бота или
`startapp=ref_<id>` для настроенного Mini App. Правила начисления бонусов не меняются.
Схема БД не меняется. Изображение и thumbnail — примерно 107 и 13 KB.

## Бот

`/start` больше не загружает каталог и не добавляет отдельные кнопки историй.
Сообщение короткое, с одной кнопкой «Открыть истории». Поддержка, /help, /terms и
обработка реферального параметра сохранены. Описания бота также укорочены и
не перечисляют сюжеты, количество которых будет меняться.

## Обновление

После переноса в ветку развёртывания:

```bash
nohup bash -c 'bash /opt/polnoch-stories/deploy/hostkey.sh update && bash /opt/polnoch-stories/deploy/hostkey.sh bot' >/var/lib/polnoch-stories/invitations-update.log 2>&1 </dev/null &
```

```bash
tail -n 50 /var/lib/polnoch-stories/invitations-update.log
```

`bot` применяет короткие описания и меню. Серверные ответы `/start` обновляются
вместе с приложением. Старые сообщения в чатах Telegram не редактируются.

Проверки: typecheck, production build, целевые Jest-тесты приглашений; приглашение учитывает
авторизованного игрока, корректно обрабатывает cancel/error/старый клиент,
не запускает Telegram для гостей и не увеличивает приветствие с ростом каталога.

Дополнительно проверена production-страница приглашения на 320/390/430 px: JPEG загружается, ссылка сохраняет ref\_, переполнения нет. Ответ для TelegramBot содержит OG-изображение внутри HEAD без JavaScript; неверный код отдаёт 404.

## Исправление незагрузившейся карточки

Оригинальный JPEG и миниатюра корректны (RGB, 1200×632 и 320×168). Публичные
закреплённые копии вернули HTTP 200 с image/jpeg и совпали по SHA-256 с файлами
в репозитории. Адреса для inline photo и OG-изображения теперь используют эти
копии. Локальная страница продолжает показывать файл приложения.

Доступность JPEG с нашей проверочной сети не доказывает его доступность из
Telegram: точная причина отказа загрузки на телефоне не подтверждена. Смена
источника медиа устраняет зависимость отправки фото от VPS/nip.io.

Подтверждённая ошибка обработки: официальный SDK сначала вызывает callback(false),
а затем shareMessageFailed с кодом. Теперь callback(false) откладывается на
микрозадачу. USER_DECLINED означает отмену, MESSAGE_SEND_FAILED, MESSAGE_EXPIRED
и UNKNOWN_ERROR — сбой, UNSUPPORTED — запасной способ отправки. Обработчик
снимается при завершении или таймауте. Ошибка сбрасывает кеш prepared message.
При обычной отмене и неопределённом таймауте повторная отправка не открывается.

После обновления создайте приглашение заново: уже созданное в Telegram сообщение
содержит прежний URL картинки. Нативная отправка требует проверки на телефоне;
автоматические проверки используют имитацию Telegram и не отправляют сообщения
реальным адресатам. Для этого исправления достаточно hostkey.sh update, без bot
и без изменений Cloudflare.

Для превью также отключена потоковая выдача метаданных (`htmlLimitedBots: /.*/`).
Единственный динамический generateMetadata в приложении — приглашение, без
сетевых запросов. Его OG-теги теперь находятся в исходном HEAD для любого
User-Agent, включая TelegramBot; до исправления они приходили в BODY.

Проверки исправления: 13 целевых тестов, typecheck и production build. Браузерная
проверка с официальным SDK и имитацией native bridge покрывает успех, отмену,
сбой с согласием/отказом от ссылки, истёкшую карточку и старый клиент. После
ошибки повторный клик заново готовит карточку; после успешной отправки кеш
сохраняется. OG-теги проверены внутри HEAD для TelegramBot, TelegramBot (like
TwitterBot) и обычного браузера, невалидный код по-прежнему отдаёт 404.
