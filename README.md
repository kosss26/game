# Полночь — интерактивные истории в переписке (Telegram Mini App)

Игрок переписывается с персонажами в интерфейсе мессенджера. Каждый день — новая глава на 10–20 минут, решения переходят из дня в день и ведут к разным концовкам.

В комплекте две истории:

- **«Белый шум»** — детектив: 7 дней (~120 минут), 7 чатов, 14 улик, 6 концовок, одна из них секретная. Полная «библия» сюжета для авторов — `content/stories/beliy-shum/BIBLE.md`.
- **«Тихий час»** — мистический триллер: 5 дней, 4 концовки.

## Возможности

**Игрокам**
- Чат с реалистичным набором текста, статусами «в сети / печатает… / не в сети», несколько персонажей в одном чате.
- Выборы, ввод текста (`{name}` подставляется в реплики), паузы в реальном времени, которые переживают закрытие приложения.
- Прогресс сохраняется на сервере: можно закрыть Telegram посреди дня и продолжить с того же места.
- Флаги переходят между днями, а на финал влияет накопленное доверие.
- Экран итогов дня: цитата, «как выбирали другие» (один голос на игрока), таймер следующего дня, коллекция концовок, перечитывание переписки.
- Скорость: «как в жизни», «быстро», «мгновенно».

**Монетизация и рост**
- Следующий день открывается через N часов после завершения предыдущего (`@wait`).
- Пропуск ожидания за Telegram Stars, сезонный пропуск на всю историю.
- Реферальные ссылки: за каждого приглашённого друга — бесплатный пропуск.
- Уведомления в боте, когда открывается новый день (текст задаётся в `@push`).

**Авторам (Студия, `/admin`)**
- Редактор скрипта с проверкой «на лету», исходник сохраняется для повторного редактирования.
- Предпросмотр черновика в настоящем плеере со стартовыми флагами.
- Анализ графа: недостижимые сцены, битые метки, бесконечные циклы.
- Публикация неизменяемыми снапшотами: игроки посреди дня доигрывают ту версию, которую начали.
- Аналитика: воронка по дням и выручка в Stars.

## Стек

Next.js 15 (App Router, server actions), React 19, TypeScript, Tailwind, PostgreSQL, Telegram Bot API.

## Быстрый старт (без настроек)

```bash
npm install
npm run seed      # загрузит «Тихий час» в локальную демо-базу .data/local-db.json
npm run dev       # http://localhost:3000
```

Без настроек базы приложение работает на локальной JSON-базе. Она рассчитана только на разработку. Студия `/admin` в dev-режиме открыта, если не задан `ADMIN_PASSWORD`.

## База данных

Приложение выбирает источник данных автоматически:

| Переменные | База |
|---|---|
| `DATABASE_URL` | свой PostgreSQL 14+ — **рекомендуется** |
| `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` | Supabase |
| ничего | локальная демо-база (только разработка) |

Код запросов одинаковый для всех вариантов. Схема — `supabase/schema.sql`, обычный PostgreSQL без зависимостей от Supabase. Она применяется командой `npm run db:migrate`, а в Docker — автоматически при каждом старте; повторный запуск безопасен.

Если база создана старой версией (v0.1), сначала выполните `supabase/migrations/002_release_v1.sql`.

## Деплой на свой сервер (Docker) — рекомендуется

**Нужно:** VPS с Docker (от 1 vCPU / 1 ГБ RAM, Ubuntu 22.04+) и домен, A-запись которого указывает на IP сервера. HTTPS обязателен для Telegram Mini App — сертификат выпустит Caddy автоматически.

```bash
git clone <repo> polnoch && cd polnoch
cp deploy/.env.example .env
nano .env                                    # домен, токен бота, пароли и секреты

docker compose up -d --build                 # Postgres + приложение + HTTPS + уведомления + бэкапы
docker compose run --rm tools npm run seed   # загрузить и опубликовать «Тихий час»
docker compose run --rm tools npm run bot:setup   # webhook, меню, команды бота
```

Готово: откройте бота в Telegram и нажмите «Истории».

Что поднимается:

| Сервис | Назначение |
|---|---|
| `db` | PostgreSQL 16; данные в томе `pgdata` |
| `app` | приложение; при старте применяет схему |
| `caddy` | HTTPS (Let's Encrypt) и проксирование на приложение |
| `cron` | каждые 15 минут рассылает уведомления «открылся новый день» |
| `backup` | ежедневный `pg_dump` в `deploy/backups/`; хранятся 14 последних |

Полезные команды:

```bash
docker compose logs -f app                       # логи
git pull && docker compose up -d --build         # обновление
docker compose run --rm tools npm run seed       # после правок в content/
docker compose exec db psql -U polnoch           # консоль БД
# Восстановление из бэкапа:
docker compose exec -T db pg_restore -U polnoch -d polnoch --clean < deploy/backups/polnoch-2026-11-04.dump
```

**Без Docker.** Нужны Node.js 22, PostgreSQL и любой reverse proxy с HTTPS (nginx или Caddy):

```bash
npm ci && npm run build
npm run db:migrate && npm run seed && npm run bot:setup
node .next/standalone/server.js      # нужны также .next/static → .next/standalone/.next/static
```

Процессом удобно управлять через systemd или pm2. Для уведомлений добавьте в crontab: `*/15 * * * * curl -fsS -H "Authorization: Bearer $CRON_SECRET" https://<домен>/api/cron/notify`.

### Настройка бота
1. Создайте бота в [@BotFather](https://t.me/BotFather), затем выполните `/newapp` и укажите URL приложения. Короткое имя приложения впишите в `APP_SHORT_NAME`.
2. Платежи в Stars работают без дополнительной настройки: валюта `XTR`, провайдер не нужен.
3. `npm run bot:setup` настроит webhook, кнопку меню, команды и описание бота.

### Деплой на Vercel + Supabase (альтернатива)
Добавьте переменные из `.env.example` в настройки проекта. `vercel.json` запускает cron каждые 30 минут: на Vercel это требует тарифа Pro, на бесплатном используйте внешний планировщик.

### Администраторы
- В браузере: `/admin/login` и `ADMIN_PASSWORD`.
- Из Telegram: Telegram ID в `ADMIN_TELEGRAM_IDS` или запись в таблице `admin_users`. На главной появится кнопка «Студия».

## Формат сценария

Истории лежат в `content/stories/<slug>/`: `story.json` (метаданные, персонажи, концовки) и `day1.story … dayN.story`. Тот же формат принимает редактор в Студии.

```
@title Неизвестный номер        @minutes 12      @wait 12h
@recap Цитата на экране итогов  @teaser Тизер следующего дня
@push Ася: ты не спишь?         (текст уведомления, когда день откроется)
@char nina Нина | color=#4fae9b (персонаж только этого дня)

asya: реплика персонажа         ME: реплика игрока      SYS: системное
...  [typing 1500ms]  [delay 500ms]  [pause 2m Ася не в сети]

:: метка                        -> метка                END   |   END dawn
IF trust >= 3 && !lied -> метка SET trust += 1, met = true
[if told] asya: условная реплика

CHOICE: Подсказка над вариантами
- Ответ, отправляемый в чат -> метка [set trust += 1]
- Вариант без перехода продолжает после блока
- (Действие в скобках — не отправляется как сообщение)
- Секретный вариант [if knows_secret]

INPUT name: Как вас зовут?      ({name} в любом тексте)
{спал|спала}                    форма по роду игрока (SET gender = "f")
```

**Несколько чатов, вложения, улики:**

```
@chat group Дача ❄️ | kind=group | members=mark,dima    (или в story.json → meta.chats)
[chat group]                    дальше реплики идут в групповой чат
[chat mark]                     …а это — в личку Марку

[history] … [/history]          архивная переписка: без набора и времени

mark: [фото] Описание снимка     mark: [голосовое 0:19] Расшифровка
mark: [гео] Лодочный сарай       mark: [файл voice.ogg] Описание
mark: [пересланное Лера] Текст   mark: [удалено] Исчезнет через 3 секунды

SET clue_boots                  улика из story.json → meta.clues попадает в блокнот
```

В плеере появляются вкладки чатов с непрочитанными, уведомления из других чатов и блокнот улик.

`END <id>` в последнем дне фиксирует концовку из `story.json → meta.endings`. Тест `src/lib/content/__tests__/content.test.ts` прогоняет 3000 случайных прохождений каждой истории. Он проверяет, что все дни завершаются, а все объявленные концовки достижимы.

## Архитектура

```
src/
├── app/                      страницы: /, /story/[id], /play/[id]/[day], /legal, /admin/*
│   └── api/                  telegram/webhook (оплаты, /start, рефералы), cron/notify
├── components/
│   ├── chat/                 плеер: ChatPlayer, сообщения, панели выбора/ввода/паузы
│   ├── screens/              главная, страница истории, итоги дня, оплата
│   ├── ui/                   аватары, иконки, процедурные SVG-обложки, таймеры
│   └── admin/                студия
├── lib/
│   ├── engine/               чистый рантайм сцен и безопасные выражения (без eval)
│   ├── parser/               DSL → сцены
│   ├── game/access.ts        правила открытия дней (ожидание, пропуски, релизы)
│   ├── actions/              server actions: player, admin, auth
│   ├── auth/                 подписанные HMAC-сессии, проверка Telegram initData
│   ├── content/              импорт/публикация, загрузчик content/
│   └── db/                   адаптеры БД: postgres.ts (свой Postgres), local.ts (демо)
content/stories/              истории
supabase/                     схема (обычный PostgreSQL) и миграции
scripts/                      seed, bot-setup, migrate
deploy/, docker-compose.yml   развёртывание на своём сервере
```

### Безопасность
- `initData` от Telegram проверяется по HMAC: сравнение с постоянным временем выполнения, срок годности 24 часа.
- Сессия — подписанный токен в httpOnly-cookie (`SameSite=None; Secure`). Тот же токен дублируется в запросах, поэтому вход работает и при заблокированных сторонних cookie.
- Каждый admin action проверяет права на сервере.
- Контент дня отдаётся только после проверки доступа, поэтому платный пропуск нельзя обойти через URL.
- Сохранять прогресс можно только по «билету», который сервер выдал при открытии дня. Входные данные ограничены по размеру.
- Webhook проверяет `X-Telegram-Bot-Api-Secret-Token`. Выдача покупок идемпотентна по `telegram_payment_charge_id`.
- БД доступна только серверу приложения: в Docker Postgres не публикуется наружу. Для Supabase включён RLS.

| Команда | Что делает |
